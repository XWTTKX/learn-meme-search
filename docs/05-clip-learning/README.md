# 05 · CLIP、InfoNCE与困难负样本

## 先用生活例子记住两个方向

给两张图和两句说明：图 A 是趴在桌子上的人，图 B 是睁大眼睛的猫；文字 A 是「累了」，文字 B 是「猫咪吓一跳」。训练既问「每张图最像哪句说明」，也问「每句说明最像哪张图」。一个方向的正确不保证另一个方向正确。例如分数矩阵的两行是 `[0.8, 0.2]` 和 `[0.85, 0.9]`，两张图都选对了文字；但第一列最高分是第二行的 0.85，文字 A 反而选错了图。双向损失正是为两种竞争关系都提供训练信号。

```text
图 A ──图像塔──► v_A ──┐          ┌── t_A ◄──文本塔──「累了」
图 B ──图像塔──► v_B ──┼─ 相 似 度 ┼── t_B ◄──文本塔──「猫咪吓一跳」
                       │          │
                       └── 2×2 ───┘
                          文 A   文 B
                    图 A [  +      -  ]  行内 softmax：图选文字
                    图 B [  -      +  ]
                            ↓      ↓     列内 softmax：文字选图
```

把 softmax 概率写成 p，交叉熵对某个 logit 的梯度是 `p - y`。例如一行分数是 `[2,1]`、第一个是正例，则概率约 [0.7311, 0.2689]；梯度为 [−0.2689, +0.2689]。梯度下降会把正确项拉高，把错误项压低；若错项得分很高，它的梯度也更大。这也是困难负样本较有信号、假负样本较有破坏力的原因。

## 在 Python 里算两方向，不下载模型

```python
from math import exp, log

def ce(row, target):
    top = max(row)
    return top + log(sum(exp(v - top) for v in row)) - row[target]

def paired_loss(matrix, temperature):
    logits = [[v / temperature for v in row] for row in matrix]
    image_to_text = sum(ce(row, i) for i, row in enumerate(logits)) / len(logits)
    text_to_image = sum(ce(col, i) for i, col in enumerate(zip(*logits))) / len(logits)
    return image_to_text, text_to_image, (image_to_text + text_to_image) / 2

print(paired_loss([[.8, .2], [.4, .6]], .2))
print(paired_loss([[.8, .2], [.6, .4]], .2))
```

第一行输出约 (0.1809, 0.1269, 0.1539)。第二行改错配对矩阵里的一个排序后，总损失更大；对两个矩阵分别把温度改成 0.05，比较对应变化。严格来说，这段代码假设图文一一配对且对角线为正例；多正例或一个 batch 有同图多文本时应该提供明确的掩码，而不是用它直接训练。

## 设计一次对比才知道要不要微调

| 发现的错误 | 先做的廉价排查 | 何时才考虑训练 |
|---|---|---|
| 一堆有明确台词的图片搜不到 | 单独跑 OCR，核对分词和文本清洗 | OCR 可读但语义近似查询仍差 |
| 同模板各种配文打成一团 | 测 OCR/字幕分路，标出语义反例 | 原图与配文合起来才能判断，模型持续犯错 |
| 短句完全没方向 | 按意图分组，比较直接文本与显式解释 | 有足够同分布数据，且简单改写不够 |
| 图文向量自检正常但是返回错图 | 核对模型/manifest 版本和 ID 映射 | 排除错位后才做 |

记一条容易漏的边界：训练队列、验证图和测试图不能靠同一个模板扩增到三份。取同一图重复压缩不算三个独立正例。先切模板族，再挖困难负例；把未曾审查的测试集保留到最终。

## 为什么文字能搜图片

一张图和一句话不是同一种输入，故先各自编码。假设文字编码器返回查询向量 $t$，图像编码器返回图片向量 $v$。两者维度相同是必要条件，真正让它们可比的是训练：同一个空间里，让匹配图文具有较高内积。比如查「不想上班」，图片本身可能没有文字，只画了趴在桌上的人。能否检出取决于模型是否学过这类语义联系，而不取决于 tokenizer 有没有分析出「上班」这个词。

图像特征矩阵形状为 $N\times D$；查询批次为 $B\times D$。归一化后，用查询矩阵乘图片矩阵的转置，得到 $B\times N$。脚本只处理一个查询，因此从结果取第 0 行再排序。图片如果换了预处理、模型或投影，缓存中的向量也必须重建；只保证维度相同不能保证同一向量空间。

## 手算一轮双向对比学习

设同批两对已配对图文的单位向量相似度如下。行是图，列是文，对角线是配对目标。

| | 文字 1 | 文字 2 |
|---|---:|---:|
| 图 1 | 0.8 | 0.2 |
| 图 2 | 0.4 | 0.6 |

设温度 $\tau=0.2$，logits 为 $[[4,1],[2,3]]$。图 1 的分类损失是 $\log(1+e^{-3})\approx0.0486$。图 2 是 $\log(1+e^{-1})\approx0.3133$，图→文平均约 0.1809。转置矩阵后，两行正负差都是 2，文→图平均约 0.1269。两方向平均约 0.1539。归一化后的余弦相似度是排序信号；经过 softmax 的值还依赖同批有哪些候选，不等于业务上「相关」的概率。

把温度减半，两图中较大的正确间隔会被放大，当前例子的损失下降；若把第二张图的正确项和错误项交换，减小温度会让错误更严重。训练中用稳定的交叉熵或 logsumexp，而不是直接计算大数的指数。常见的可训练缩放表示为 $\exp(s)$，相当于 $1/\tau$；检查上游实现时先看缩放在哪里乘，避免重复乘。

## 从零样本到训练的对照顺序

1. 冻结训练和评测文件，先用预训练模型直接做文本到图像，记录每类查询错误。
2. 把图像描述、OCR 加入词法路；记录新增相关结果来自哪一路。改变特征可能比微调更便宜。
3. 如仍有大量语用错误，基于训练库检索错误候选做困难负例审查：词面近、语义相反的「想上班」可以是负例；另一张「不想上班」不应因恰好没配对就当负例。
4. 可选择先冻结编码器、训练小投影层做 sanity check；要在同一测试切分和同一候选目录上与零样本做配对比较，并保存失败切片。这个步骤是练习方案，本仓库不声称已完成训练。

### 练习与答案

同模板「给我加油」和「别再催了」视觉非常像，是否需要把整个模板视为同一个正例？不一定。模板能共享视觉语义，但配文可能改变意图。评测应按查询判相关；数据划分则可以按模板族分组，防止不同字幕版本跨集合造成泄漏。批内有多个等价正例时，可以用多正例掩码或避免把它们放进互为负例的批次。若只扩大 batch，负例变多，假负例也可能变多，因此得监控语义冲突比例。

源码阅读：[CLIP 论文](https://arxiv.org/abs/2103.00020)、[Chinese-CLIP 论文](https://arxiv.org/abs/2211.01335)。重点找相似度矩阵、配对标签和损失的两个方向，不必先读完分布式训练。

图像编码器得到 v，文本编码器得到 t，各自 L2 归一化后用 `s=tᵀv/τ` 构造相似度。对一个包含 B 对图文的批次，每张图对应的文字是正例，其他文字默认作为负例；交换图文方向后再平均两个交叉熵损失。

单方向损失：`L_i = -log(exp(s_ii) / Σ_j exp(s_ij))`。温度 τ 影响分布尖锐程度；它不是业务上的置信度阈值。模型输出的余弦相似度也不能直接解释为“有80%的概率相关”。

## 为什么表情包容易出现假负例

同一张图可能配“收到”“好的”“没问题”，不同图片也可能表达同一种情绪。如果把这些全部当负例，训练目标会强迫语义相近的样本分离。解决方向包括同模板去重、同义查询分组、多正例损失、人工审查困难负例。

困难负例来自基线检索中“分数高但经人工确认不相关”的图片。不能把模型自己没召回的图片自动视为负例，也不能用测试集挖训练负例。先冻结大部分编码器，只训练投影层可降低资源成本，但应与零样本基线比较，不保证一定提升。

验收：手算 B=2 的相似度矩阵，说明批量增大对负例数量和显存的影响。扩展实验需记录批量、温度、学习率、冻结层、随机种子与验证集早停规则。
