# 15 · 简历写法与成果证据

## 用证据决定动词

| 你手上有的证据 | 可以写 | 暂不宜写 |
|---|---|---|
| 原创样例、代码及测试 | 实现可复跑的 BM25、融合和请求级评测 | 真实线上效果 |
| 实际跑过自有图文索引 | 接入预训练模型，统计同库文字与向量召回 | 自研或训练图文模型 |
| 跑过独立标注集的同口径对照 | 给出测试集大小、K、前后指标及主要错误 | 把合成数据或上游指标算到自己的提升里 |

可先写：「搭建中文表情包检索基线，基于 BM25 与 RRF 设计多路候选，记录 Recall、MRR、NDCG 和无正例查询，使用合成案例验证分路诊断」。面试被问数字时，带上运行命令、固定版本和一条错误案例。若未跑图像推理，主动说明图文路是接入脚本，输出还要用真实图片验证。

## 未完成实验时的真实写法

“实现中文表情包检索教学原型，完成文字召回、排名融合和Recall/MRR/NDCG评测；调研Chinese-CLIP并设计多模态检索实验。”只有运行真实图片路径后，才写“接入Chinese-CLIP实现图文检索”。

## 完成实测后再填写

“基于[有使用权的N张图片]构建中文表情包检索系统，通过[改进]使固定测试集上的[指标]由[A]提升至[B]，在[硬件与并发]条件下P95为[数值]；分析[具体错误类型]并完成[消融]。”

方括号是待填事实。示例数据满分、上游作者结果、论文结果不能放到自己的成绩里。没有线上实验就写离线指标，不写“业务CTR提升”。

## 每条简历的证据包

代码commit、数据来源与授权、配置、命令、原始日志、评测口径、失败案例。面试官追问时能从一个数字回到完整实验，而不只提供截图。

职责边界写清：预训练模型来自上游；你独立完成哪些数据、代码和评价。使用AI辅助代码并不阻止作为学习项目，但需要自己理解、验证并能修改关键实现。
