# 12 · 三阶段实战与六周安排

## 实验一：离线重现三种融合结果

```bash
python3 scripts/fusion_lab.py
```

这里的视觉榜是故意手填的，不要写成 Chinese-CLIP 运行结果。词法路使用真实代码和手写图库。观察下列三种变化：

- 「累成狗」没有词面命中，视觉榜提供两个独有正例。把视觉路关掉，Recall@2 应从 1 变成 0。
- 「下班」的相关 ID 两路都含有，但词法把它排第一，视觉排第三。改变单路截止位置，从 3 截到 2，观察视觉是否还有机会对它加分。此处「独有」以送入融合的池为准，和 @2 不同。
- 「量子力学」没有正例，但词法因「力」仍有命中，说明无答案询问不能靠分数非零就返回。指标为 null，把无答案错误返回率独立记录。

把输出保存为自己的实验记录，另挑一条在 RRF 中被双路的低相关结果反超的查询。解释为什么调小 c 可能更偏向单路靠前结果，但并不保证命中靠前。建议先验证「词法最强的一类」与「图文最强的一类」是否都没明显退化，再讨论增加路线。

## 实验二：把手填榜替换成真实模型榜

选择已获权的图片、记录模型权重版本、人工标一批训练外查询。先跑词法、图文各自的 TopK，保存逐查询候选 ID；再用同样的输入调用融合。分别记录召回和首位准确，挑三个代表性失败保存原因，包括图文误召回、词法误召回、融合反超各一种。没有权重或图片时只完成实验一；没有真实标签时只评估管线是否可运行。

## 实战A：可解释基线

运行标准库demo；逐步替换文字标签；手算一个BM25排序与RRF排序。产出：字段文档、错误分析、评测脚本。完成标准是能解释每个返回结果。

## 实战B：真实图文检索

准备有使用权的图片与标注；跑可选Chinese-CLIP脚本；补向量缓存；对比BM25、CLIP、融合。产出：冻结测试集、模型版本、消融表、20个bad case。至少保留一个没有改善的实验，解释原因。

## 实战C：只选一个深入点

三选一：困难负例微调、ANN精度延迟权衡、OCR与语义融合。不要同时做十个模型而没有可信评价。资源不足时优先融合与评测，模型训练放后。

| 周 | 搜索项目 | 与推荐项目共享的知识 |
|---|---|---|
| 1 | 基础、源码、文字基线 | Recall/NDCG与数据划分 |
| 2 | 图片与标注、零样本CLIP | 向量、负采样 |
| 3 | 融合消融、bad case | 多路召回 |
| 4 | 一个深入实验 | 排序与目标一致性 |
| 5 | 缓存、压测与复现 | 离在线一致性 |
| 6 | 简历、模拟面试 | 取舍与失败复盘 |

此表建议两个项目合计每周10–15小时；已有基础可压缩，没有GPU不影响第一阶段。验收以产物为准，不以读完章节数为准。
