# 08 · 词法与融合：把「命中」拆到字符、候选与名次

> 本章目标：能独立写出小语料的倒排表，解释 BM25 的三个组成部分，比较两个融合方案，并用反例推翻「多一路召回一定更好」。

## 8.1 先把用于搜索的信息拆开

一张图片可以有多个信号来源。想找台词时，图片上的文字证据最有价值；想表达情绪时，画面或者人工语义标签更重要。不要在导入时把 OCR、手工标签和模型生成描述都混到同一字符串，之后就没办法知道哪个信号产生了一次错误匹配。

| ID | 图片原文字 | 图像内容 | 作者标注 | 查「不想上班」时 |
|---|---|---|---|---|
| A | 今天也不想上班 | 趴在桌前 | 疲惫、打工人 | 台词与意图都合适 |
| B | 无 | 卡通人物有黑眼圈 | 困倦 | 语义可用，词面不好找 |
| C | 上班加油 | 挥拳 | 鼓励 | 同词，不同情绪 |
| D | 已经下班了 | 兴奋地跑 | 开心 | 场景相关但意图不同 |

当前 demo 为了简化接口只有 `text` 字段。要做真实评测，先分别记录这些字段，并通过同一个图 ID 连接。每次只变一种信号：例如把 OCR 作为词法的单独路，对比并排保存词法原标签、OCR 和图文三个排名。图像版权、标注意图和模板族见 [第 07 章](../07-data-labeling/README.md)。

## 8.2 从正向表推到倒排表

构造三个字符串，按字切分。正向表从图片 ID 找文字，倒排表从一个字反过来找文档：

```text
正向                              倒排
A: [困,倦]                       困: (A,1), (B,2)
B: [困,困,累]                    倦: (A,1)
C: [开,心]                       累: (B,1)
                                 开: (C,1)
                                 心: (C,1)
```

查「困累」只走「困」与「累」两张表。A 只加一次「困」的贡献；B 要加「困」和「累」；C 完全不访。给每篇文档保存长度；对每个词，倒排表长度正是 DF。这里还没有把 BM25 公式写进倒排列表，它只改变访问路径，不改变得分定义。

### 编码练习：构建一份可读的小倒排表

```python
import sys
from collections import Counter, defaultdict
sys.path.insert(0, "scripts")
from retrieval import tokens

docs = {"A": "困倦", "B": "困困累", "C": "开心"}
postings = defaultdict(list)
lengths = {}
for doc_id, sentence in docs.items():
    counts = Counter(tokens(sentence))
    lengths[doc_id] = sum(counts.values())
    for term, freq in counts.items():
        postings[term].append((doc_id, freq))

candidate_terms = defaultdict(dict)
for term in dict.fromkeys(tokens("困累")):
    for doc_id, count in postings[term]:
        candidate_terms[doc_id][term] = count
print("lengths", lengths)
print("candidates", dict(candidate_terms))
```

预期长度是 A=2、B=3、C=2，候选是 A 的「困」1 次和 B 的「困」2 次、「累」1 次。继续实现倒排版时可用本仓库的扫描版对照，尤其检查无结果、最高频词、同分与短 query。同一组假设下，两个实现的名次和得分应该一致。继续追求速度应对上真实的流水线瓶颈，高频字的 postings 很长，倒排不会让每条查询都很便宜。

## 8.3 BM25 的每一项为什么在这儿

设图库大小为 N，文档词频 f，文档长 dl，平均长 avgdl，含该词的文档数 df。实现可拆成：

- **IDF** = ln(1 + (N − df + 0.5)/(df + 0.5))。更少文档包含的词提供更强区分度。
- **长度项** = k1 × (1 − b + b × dl/avgdl)。b 控制长度修正，b=0 不使用长度。
- **词频权重** = f × (k1+1)/(f+长度项)。次数越多通常越强，增益递减。

与「匹配到一次就加 1」相比，这是对可解释差异的控制，而不是关于词意义的学习。换语料会影响 IDF、平均文档长度、所有分数的量级；不要拿固定的分数阈值直接跨库。

### 小语料手算

用「累」「很累」「笑」查「累」，分别长 1、2、1。N=3、df=2，IDF≈.4700，avgdl=4/3。第一篇长度比 .75，长度因子 .8125，第二篇长度比 1.5，长度因子 1.375。代入 k1=1.5，得到 0.5296 和 0.3837，「笑」没有结果。如果改动只是把第二个标签扩写成更丰富的画面描述，可能让它更容易被别的 query 找到，却对这条 query 因长度惩罚产生不利。单条示例用来理解方向，真实调参需要对同一批验证查询。

### 中文按字为什么既好用又危险

优势：不需要词表，受新造词影响较少，单字查询也可以匹配。风险：两个反义句共享大量字符，「不想上班」能命中「想上班」。可以把二元组与字符并行，为长查询用短语约束，同时保留「猫」这种单字回退。分词策略改变了索引和 query 两端；正确的消融必须重新建库、保持其余条件固定。

## 8.4 RRF 手算：它不看 BM25 和 CLIP 的原分

设词法给 [A,X]，图文给 [B,X]，正例是 A、B。两个候选列表里的名次可以直接用，哪怕词法分数是 10.5，图文分数是 .27。RRF 用每一路的 1/(c+名次) 累加：

| 候选 | 路一贡献 | 路二贡献 | c=60 总分 | 最终结果 |
|---|---:|---:|---:|---|
| A（正例） | 1/61 | 0 | .01639 | 第 2 |
| B（正例） | 0 | 1/61 | .01639 | 第 3 |
| X（错误） | 1/62 | 1/62 | .03226 | 第 1 |

```text
词法              A ── X
图文              B ── X
                       ╲╱ 双路都有
融合 (3 个)       X → A → B
展示 (K=2)       X → A      B 被截掉
```

合并候选覆盖为 1，但展示 Recall@2 为 .5。这个例子让人直观看懂两件事：融合结果比任何单路候选多，不代表首屏更好；两路都给靠前名次也不保证是正例，两个模型可能共有同一种偏差。

### 修改参数前先问意图

如果大量用户确实在找固定台词，可以对有明确引号或准确 OCR 匹配的请求尝试词法保留位；对情绪类查询多给图文候选。策略会对误判断的意图产生代价，例如把所有带引号的词都当作固定台词。用配对的验证计划估计「准确台词首位恢复」「语义正例还有没有入池」，避免只看总体平均。

候选重复也会改变结果。当前实现先将每路相同 ID 去重，之后再编号；一张图在同一路出现三次不会拿三笔。同模板不同 ID 不在这个去重范围，若展示层按模板聚合，就要同步评估模板级指标。

## 8.5 跑一次分路实验

```bash
python3 scripts/fusion_lab.py
```

视觉榜来自手填，便于独立观察 RRF；真实 CLIP 需要另外跑。

1. **「累成狗」**：词法没有命中，视觉榜两张正例都是新增。查看 `visual_only_positive`，注意它按入池名次而不是首屏名次定义。
2. **「下班」**：正例在视觉第三、词法第一，融合第一。查看为什么 `lexical_only_positive` 为空：正例存在于视觉 Top3，不代表视觉 Top2 就命中。
3. **「猫」**：两路都有正例，融合把它提到第 1。Recall@2 没变，但 MRR 从 .5 变 1。
4. **「量子力学」**：标签为空仍有候选，需单独报告错误返回，不当作 Recall=0 去平均。

做正式实验时将每题记录为：query、意图、正例、两路名次、并集大小、最终成绩、排除理由。对无答案 query，要定义怎样返回空或建议改写。用第 10 章的口径解释结果，而不是只记一个新增候选数量。

<details>
<summary>自查：c 越小就一定越好？</summary>

c 小让一个列表中第一与第二名的差距更明显；双路计数、候选同分、最终截断、数据意图仍会共同决定结果。用 c=0 改手算例子，三个分数会打平；字典序可能使 A、B 先出现。不能据此声称 c=0 对其他图片也最好。
</details>

<details>
<summary>自查：只显示视觉 Top1，能否用视觉 Top3 的 Recall 宣传展示效果？</summary>

不能。Top3 可以作为「候选阶段」的指标，展示只有一张应单报 Top1。对照时同时固定单路预算、展示 K 和过滤规则，记录两个不同指标。
</details>
