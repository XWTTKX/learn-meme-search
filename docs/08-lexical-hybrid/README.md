# 08 · OCR、BM25与RRF融合

## 倒排索引像一本反过来的目录

```text
文档正向表                       倒排表（token → 文档、词频）
A → [困, 倦]                    困 → [(A, 1), (B, 2)]
B → [困, 困, 累]                倦 → [(A, 1)]
C → [开, 心]                    累 → [(B, 1)]
                                 开 → [(C, 1)]
查询“困累” → 只遍历“困”和“累”对应的候选 → 累计各词贡献
```

当前仓库为了易读，遍历全库再检查 TF；它没有真正实现倒排查询。上图是可做的下一步。你仍需要每个文档的长度、平均长度、每词的 DF，与扫描版使用完全一样的 tokenizer 和同分规则。实现后固定十条查询，比较得分与排序，不应因为换数据结构而改变召回含义。两种实现量级不同：扫描版约要看每篇文档与每个查询词；倒排版主要访问这些词的 postings，总量仍受高频 token 影响。

## 给每个信号一个位置

| 文档 | OCR 文本 | 人工语义 | 画面信息 |
|---|---|---|---|
| A | 今天也不想上班 | 打工人、疲惫 | 趴在桌上 |
| B | 没有可读文字 | 倦、困 | 黑眼圈卡通人物 |
| C | 上班加油 | 鼓励 | 挥拳给自己打气 |
| D | 我好累 | 抱怨 | 流泪的小狗 |

查「今天也不想上班」可给精确词法更高优先；查「累成狗」不能只按 OCR，也不能因为有狗就排前。实际融合可保存路级 rank 和候选来源，下游打分时用「是否精确匹配」作为额外特征，而不是把所有文本字段无区别地拼接。没标签的小样例先用 RRF；有标签后比较规则和训练策略，同时统计错序发生在哪些意图。

## 自己算一遍候选预算

```text
词法候选 Top2    A (正) → X (负)
图文候选 Top2    B (正) → X (负)
K = 2，正例为 A 与 B
c = 60：
  X: 1/62 + 1/62 = 0.03226
  A: 1/61        = 0.01639
  B: 1/61        = 0.01639
融合列表 X → A → B，Top2 只保留一个正例。
```

候选并集覆盖为 2/2，但展示 Recall@2 为 1/2。这是「两路交集规则压过正确排序」的最小反例。可试 `c=0`，此时 X 得分 1、A 与 B 各 1，当前字典序会先给 A 和 B，但这个具体表现也依赖 ID。不要为了这个例子把线上参数固定为 0；系统可以同时检验名单中真实相关性与响应时延。另一个策略是为每路显式保留一个首位候选，再让剩余名额由融合补齐，缺路时回填。

<details>
<summary>练习：增加每路候选数，一定能提高融合后的 Recall@K 吗？</summary>

不一定。举例把 X 从两路原本截止位置之后引入池里，只要它跨路累加就可能比单路正例分数高，并把那个正例挤出展示 TopK。理论并集覆盖不下降；固定 K 的最终 Recall 可能上升、持平或下降。请对照记录候选并集上限和最终得分，且比较相同展示 K。
</details>

## BM25 的三项作用

实现见 [retrieval.py](../../scripts/retrieval.py)。对查询中的每个不同 token，找文档里的出现次数 $f$，累加：

$$
\log\left(1+\frac{N-df+0.5}{df+0.5}\right)
\frac{f(k_1+1)}{f+k_1(1-b+b\,dl/avgdl)}.
$$

第一项让冷门词更有区分度；第二项的分式让重复词边际收益递减；括号中的长度修正约束长标签天然命中更多字的问题。默认 $k_1=1.5,b=0.75$。这版对中文按字切分，优点是依赖少、无词表，缺点是「想上班」与「不想上班」高度重叠。替代方案是字二元组或分词，配合短词回退；比较时要同时换索引和查询的 tokenizer。

手算：3 个文档分别是「累」「很累」「笑」，长度为 1、2、1。查询「累」的 DF 是 2，IDF 为 $\ln(1+1.5/2.5)=0.4700$。平均长度是 4/3；第一个文档的长度修正为 $1-0.75+0.75\times0.75=0.8125$，得分约 0.5296。第二个文档修正为 1.375，得分约 0.3837。两个文档都只命中一个词，短文档更靠前。「笑」零分，不返回。若把 $b$ 设为 0，两个相关文档在这个例子里同分。

## RRF 为什么在没有标签时有用

词法候选 `[A,B]`，图文候选 `[C,B]`。融合分数是每路存在时加 $1/(c+r)$，其中 $r$ 从 1 起。令 $c=60$，B 的分是 $2/62=0.03226$，A、C 各 $1/61=0.01639$，因此 B 排第一。重复 ID 只在本路计第一次。相比把一个 BM25 分数和一个余弦分数相加，RRF 不需要解释两路量纲。代价是它也丢掉了间隔信息：词法路第 1 名可能是明确的图中文字精确命中，却被双路都排得一般的结果反超。

可以按意图分别做对照：输入完整台词的流量，固定词法 Top3 后再融合剩余候选；情绪类查询保留更多向量名额。验收看精确台词首位、模糊表达覆盖和候选预算三项。词法出 30、向量出 30 并不等于 60 个唯一候选；报告合并前后数量和每路独有正例，才能回答「这路值得多跑一次吗」。

### 练习与答案

对 `[A,A,B]` 和 `[B,C]`，B 两次贡献分别来自 2 和 1，而非 3 和 1。原因是实现先按出现顺序去重，再确定名次。若线上按模板去重而离线按图 ID 去重，指标也会失配；需要在评测配置里把去重阶段和实体定义写清。

文字信息通常能补齐CLIP对具体短句的弱点。先人工录入少量图中文字建立对照，再决定是否接入OCR。本仓库读取 `text` 字段，**没有调用OCR引擎**。

BM25由词频、逆文档频率和长度归一化组成。当前教学实现用中文单字和英文词分词，不依赖分词库；好处是能直接运行，缺点是“上班”和“下班”会共享“班”，精度需要词级或字符n-gram基线比较。

直接相加BM25和余弦分数容易被量纲支配。RRF使用 `score(d)=Σ 1/(c+rank(d))`，从1计名次。它能处理各通道的分数尺度差异，但丢掉分数差距，对通道截断深度敏感。默认 c=60 只是常用起点，调优在验证集完成。

## 消融实验

固定同一候选库，分别运行：文字检索、纯CLIP、RRF。先按查询类型分桶，再比较整体指标。若文字型提升而情绪型下降，检查文字通道是否噪声过大，并考虑查询意图路由或通道权重。

验收：用一个两通道、三候选的例子手算RRF。说明同一个通道重复返回某图片为何只能计一次。相似度融合后再做去重，不把重复模板占满前十。
