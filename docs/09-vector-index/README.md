# 09 · 向量索引：先证明模型能找，再证明搜索够快

> 本章先写一个精确 TopK，再手算只查一个簇为何会漏结果。最后列出建库、增量与回滚所需的产物。本仓库可选图文脚本只做精确内积，不声称已上线 ANN。

## 9.1 图编码和查询为何要分开

开发原型可以每次读图并编码，优点是容易检查输入；实际一台服务处理两次相邻查询，图库内容没变，重复跑图像塔没有意义。将图库按版本批处理，在线只编码查询，使用稳定 ID 找展示内容。

```text
写入：
图片 → EXIF/颜色/尺寸处理 → 模型图片塔 → 归一化向量
  │                                      │
  └─► 稳定 id 和可见状态                     ├─► row_to_id
                                         └─► 向量或 ANN
读取：
文本 → 同一模型的文字塔 → 归一化 → TopK 的行号 → 稳定 id → 展示
```

不要用文件枚举顺序充当永久 ID。增量写入、并行任务或换目录可能改行序。如果向量文件、ID 清单和元数据不是同一版本，分数计算会通过而显示错图。这类错误比维度不匹配更隐蔽。构建时同时写行数、维度、dtype、模型/预处理版本、ID 清单哈希以及可见目录版本。

## 9.2 精确索引用来当裁判

对于两个单位向量，平方欧氏距离 = 2 − 2×内积。所以最大内积、最大余弦和最小欧氏距离得到相同顺序。只有在单位范数时能直接用该等式；检查第 05 章 A=(2,2)、B=(1,0) 的反例。使用索引时，度量要与训练和测试一致。

下面是一个分块但仍精确的示例。分块只减少完整分数矩阵的内存，不近似削候选；对每块维护 K 个候选，最后合并即可得到全局 K。

```python
from heapq import nsmallest

def similarity(query, item):
    return sum(a * b for a, b in zip(query, item))

def topk_in_blocks(query, bank, k, chunk):
    best = []
    for start in range(0, len(bank), chunk):
        block = bank[start:start + chunk]
        scored = [(-similarity(query, vector), item_id) for item_id, vector in block]
        best = nsmallest(k, best + scored)
    return [item_id for _, item_id in best]

bank = [("A", (.9,.1)), ("B", (.7,.3)), ("C", (.1,.9)), ("D", (.4,.6))]
print(topk_in_blocks((1,0), bank, 2, 2))
```

预期 A、B，即使用 1 或 4 做分块大小也不变。若某条在本块已经排在 K 个同分规则更靠前的候选之后，它不可能进全局 TopK。正式实现要校验维度和数据类型；这里只是展示策略，`zip` 在维度不同会悄悄截短。

## 9.3 近似索引把计算花在最有希望的部分

### IVF 的一个具体漏召回

```text
精确排名： A .90  → B .70 → D .40 → C .10
倒排簇：
  近簇 [A,D]  ← nprobe=1 只查
  远簇 [B,C]  ← 整桶跳过
近似 Top2：A,D，漏掉了 B
```

聚类中心不是每个成员的精确位置。即便某个簇整体离 q 更远，簇边缘的 B 仍比近簇里的 D 更靠近。增加 nprobe 可以查更多桶，代价是访问更多向量。此例的 ANN Recall@2 为 1/2。如果唯一业务正例恰好是 D，ANN 的**业务** Recall 是 1，精确的业务 Recall 却是 0；它们不是同一个质量问题。

### HNSW 与量化在改哪个环节

| 方案 | 减少了什么 | 代价 |
|---|---|---|
| Flat | 不减少候选，精确计算 | 查询成本随目录增长 |
| HNSW | 通过图上导航跳过大量点 | 图边内存、构建成本；搜索宽度影响耗时 |
| IVF | 先选部分聚类桶，不扫全库 | 需要训练簇；边界漏召回 |
| IVF-PQ | 簇内读短码而非完整向量 | 量化偏差、训练成本，可再精排 |

细节以 [Faiss 索引说明](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes) 为准。索引参数先记下在什么设备、规模和度量下测试；不要从别人的最佳参数直接复制到另一个图库。

## 9.4 算量、延迟与内存，至少写一页实验表

100 万张图 × 512 维 × 4 字节约 2.048 GB（约 1.91 GiB）裸向量，不包括元数据、索引、运行时进程与冷启动。换 768 维约 3.072 GB。查询批有 10 个向量、全计算输出 1,000 万个 float32 值，完整分数矩阵也有约 40 MB。灰度发布如果旧版与新版一起常驻，空间需要相应余量。

在离线真实图库上保留 Flat 结果，然后按同一文档和查询切换参数。报告：

1. 候选集合、输入数、维度、设备和重复次数。
2. 精确与近似 TopK 交集、按标注的 Recall/NDCG（若有标签）。
3. 查询编码、索引、过滤各用时。区分热态 P50/P95 与首次加载。
4. 内存估计或观察、有效候选数量，特别是过滤后的短列表。
5. 每种参数相对默认配置新增或丢失的具体候选。

## 9.5 索引更新不是只覆盖一个文件

先生成整包，在隔离的进程里校验索引行数等于映射条数，随机核对图 ID、向量维度和模型版本。通过后切一个当前版本指针，再回收旧版；请求开始只读一次版本。若候选下架，检索 K 条再过滤导致展示少于 K，可以扩大候选或支持准入过滤，仍保留硬性规则。严重错误用整包回滚，不单独换一个矩阵。
