# 10 · 离线评测与bad case分析

## 用一条排名算清四个指标

查询「疲惫」的人工正例是 A 和 B；系统给 `[C,B,D]`，K=3。Recall=1/2，HitRate=1，MRR=1/2。DCG=$1/\log_2(3)=0.6309$，理想排列为两个正例占前两名，IDCG=$1+0.6309=1.6309$，NDCG≈0.3869。只说「命中率 100%」会掩盖漏召回的 A 和第一名的错误。实现看 [metrics.py](../../scripts/metrics.py)；它按唯一图片 ID 去重，且处理二元标签。若要做 0/1/2 等级标注，可另实现有等级权重的 DCG，不能沿用现有脚本后宣称它衡量了区别。

宏平均给每条查询相同权重。例：查询甲有 1 个正例命中 1 个，乙有 9 个只命中 1 个：宏 Recall 约 0.556，合并计数是 0.2。前者描述「平均每条查询」，后者更偏向正例多的查询。报告聚合方式和每类的样本量，才有可比性。

## 标注集怎么做才不偏向某一路

从词法、向量、混合的候选并集里随机打散顺序供标注，保留候选来源供事后诊断。再从未被召回的图片抽样，估算漏标。人工正例池很可能不全，因此实际 Recall 衡量的是「相对已知正例的召回」。查询可分台词、情绪、对象、动作、反讽与空结果；为每组保留短查询和完整句。用查询簇或模板族做分组切分，避免只换一个同义词就同时出现在训练和测试。

没有相关结果的查询不算 Recall，当前脚本会返回 None 并报告排除数。单独追踪这类查询的错误返回率才能评估空结果体验。另外，相关图但错模板和完全不相关也可以用分级标签区分。若把已下架的图当正例，必须明确报告因为不可用而达不到的覆盖上限。

## 如何定位策略变好或变坏

把结果表扩成：query、策略、唯一候选数、首个正例排名、新增召回 ID、丢失 ID、P95、根因。例：「收到」在词法里命中 OCR 的 A 并排第一，混合后掉到第二，而「明白了」从空结果变成 Top3 命中 B。这个现象要分两组报告，再讨论是否为精确词查询预留位置。整体分数相近并不能替代这种对照。

### 练习与答案

若搜到的是同一张图的五个压缩版本，用户是否获益五次？通常不会。可以做模板族或内容哈希级去重，标签体系同步映射到用户能感知的实体，再报告以图 ID 与以模板族计算的差异。只在展示层去重而离线仍以重复 ID 算增益会让效果虚高。

设相关集合为G、去重后的前K结果为R：`Recall@K=|G∩R|/|G|`；`HitRate@K=1[|G∩R|>0]`；MRR取首个相关项名次的倒数。多个正例时，HitRate不能替代Recall。

二值NDCG先算 `DCG=Σ rel_i/log2(i+1)`，再除以把正例排在最前面的IDCG。本仓库 `scripts/metrics.py` 对无正例查询返回None，调用方报告排除数；不静默记为满分或混入平均。

## 错误分析表

| 现象 | 优先检查 | 可验证改动 |
|---|---|---|
| 画面对、情绪错 | 文字/OCR与语境标注 | 加文字通道 |
| 图里有字却搜不到 | OCR识别、分词、停用词 | 人工转写对照 |
| 返回一堆同图 | 哈希与近重复模板 | 去重重排 |
| 旧图出现、新图缺失 | 索引与文件版本 | 增量更新测试 |
| “不要猫”返回猫 | 否定语义不足 | 结构化过滤；先核实标签 |

分别报告头部/长尾、文字/画面/情绪查询。记录候选库大小和每条查询的正例数。分桶样本太少时给区间或具体案例，不声称显著提升。

验收：用手工排序验证指标，用真实失败案例解释一个模型没有解决的问题。[实验模板](../../experiments/TEMPLATE.md)和[验证记录](../../experiments/VALIDATION.md)分别存研究结果与软件检查。
