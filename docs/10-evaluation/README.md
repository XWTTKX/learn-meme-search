# 10 · 搜索评测：先解剖一条排名，再谈分数提升

> 目标：亲手算出四个指标，能区分标注、候选、排序和截断问题，并为一次策略变更设计可以复核的对照。

## 10.1 明确评价单位：一次查询、一张图还是一个模板

同一张原图可能有压缩版、重新配字版和转格式版。如果每个文件 ID 都算一个正例，推荐前三张相同模板能获得三个命中，用户未必感觉更好。项目实现以唯一 ID 进行二元评价；若产品目标是返回多样模板，可把候选与标签都映射到模板组，再用唯一组评价。不能只把结果端去重而继续用未映射正例做分母。

查询本身也有差异：「找这句原话」与「随便给个表达烦躁的图」的可接受集合不同。固定 intent、标签来源和允许的替代图。若人工无法穷尽所有适用图，应明确 Recall 是**相对已标注的正例**，不是相对用户心中所有合理图。

## 10.2 用格子手算 Recall、HitRate、MRR、NDCG

```text
query = “疲惫”，人工正例 = {A, B, E}， K = 4
位置                   1       2       3       4        不在展示榜
返回                   X       A       Y       B             E
相关                   0       1       0       1             —
位置折扣               1     .631      .5    .431
有效 DCG               0     .631       0    .431             —
```

1. Recall@4 = 2/3。它不关心 A 到底排第 2 还是第 4，只数找回的比例。
2. HitRate@4 = 1，因为至少找回一张。只报告它无法发现还有两张没被找到。
3. MRR@4 = 1/2，因为首个正例在第 2 位。后面找到几张不会改变这次得分。
4. DCG≈1.062。理想把 A、B、E 放前三个位置，IDCG≈2.131，因此 NDCG≈.498。若把正例移到前两位，Recall 不变，NDCG≈.765。

```python
import sys
sys.path.insert(0, "scripts")
from metrics import metrics

wanted = {"A", "B", "E"}
for rank in (["X", "A", "Y", "B"], ["A", "B", "Y", "X"], ["A", "A", "B", "X"], []):
    print(rank, {key: round(value, 4) for key, value in metrics(rank, wanted, 4).items()})
print("未知正例", metrics(["A"], set(), 4))
```

重复 A 先按 ID 去掉，再截 TopK；空榜但有正例时指标为零。完全不知道正例（或者明确无答案）时函数返回 None，不要把它混到第一类。对确定的无答案，可另算错返率；对于标签不完整、尚未知是否无答案，列为待审。零不是「未评价」。

### 为什么低 Recall 可以和 NDCG=1 同时出现

取 K=1，G={A,B,E}，只返回 [B]。Recall 为 1/3；NDCG 是 1，因为一个位置已经是最理想的做法。改变 K 会同时改变理想排列长度，不应只拿两个 NDCG 数字跨 K 比较。本实现只有二元标签；若要区分「部分相关」和「特别适用」，需制定 0/1/2 标注和相应增益函数。

## 10.3 两种聚合方式回答两道问题

| 查询 | 正例数 | 命中数 | 逐查询 Recall |
|---|---:|---:|---:|
| q1 | 1 | 1 | 1 |
| q2 | 9 | 1 | 1/9 |

宏平均 (1+1/9)/2≈.556，让每个查询等权；合并计数 2/10=.2，让每个标注正例等权。某类 query 占比变化，会影响宏平均，把各切片样本数一起写出来。有海量相似的头部 query 时，可先按意图簇抽样，再做按 query 或簇重采样，而不是把同一列表的候选视为独立数据点。

## 10.4 构建标签时，给未来的自己留证据

1. 冻结当前图库版本，记下可用图、不允许显示的图、模板组。
2. 从真实需求构造查询，给每个词描述场景，不使用模型排名来定义意图。至少有精确台词、情绪、物体、否定、无答案。
3. 用至少两路候选并集做标注池，再随机采样池外图补漏；随机顺序让标注者不知道来源。
4. 对争议做复核，区分梗理解差异与质量/版权限制。冻结最终标签及修订记录。
5. 按模板族或近义查询簇切分，不把轻微改写、重复压缩图泄漏到不同集合；测试只做最终报告，不挖训练负例。

## 10.5 四层证据表：从分数回到根因

| 查询与现象 | 先看哪层 | 对照实验 |
|---|---|---|
| 「累成狗」两个正例没进词法池 | 候选 | 查 token/DF，接语义候选，多收几条同类 |
| 「收到」词法命中第一，融合掉第二 | 排序 | 固定候选，试精确匹配保留位 |
| 「不想上班」的正例被下架 | 资格 | 固定可见性规则，报告理论覆盖变化 |
| 三张同模板图占满首屏 | 列表 | 做模板分组，检查 ID 与模板口径 |
| 「量子力学」被一个「力」命中 | 无答案与阈值 | 分近义、长尾、无答案验证，记录误拦截 |

倒查每条失败时，从「有效正例是否存库」一路查到「各路有无」「融合后名次」「是否过滤」「最终展示位置」。每次只改一项、保持候选预算和 K，与旧策略配对。记录 P50/P95、候选数、具体结果与诊断；别只看四个宏指标。无线上实验时，结论局限于这份离线数据。
