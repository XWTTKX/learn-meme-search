# 图解案例：一条「累成狗」如何从空结果变成两个候选

在本章，你会亲手跑一条查询，打印分词和每一路结果、手算融合，再把「命中」与「排序好」分开判断。这里的图片语义榜是人为控制的输入，方便随时复现；真实图文模型不参与本案例。

```text
“累成狗” ──► 字符集合 {累,成,狗} ──► BM25：空
       │
       └──► 预设的示例视觉榜：[疲惫打工人, 开会犯困, 难过哭泣]
                                      │
                                      ▼
                            融合并查看首屏 Top2
                                      │
                                      ▼
                          对照人工给出的两个正例
```

## 第一步：先理解为什么什么都搜不到

```bash
python3 scripts/fusion_lab.py
```

找 `"query": "累成狗"` 这一行。项目语料中 m01 的标签包括「疲惫」、m08 包括「困倦」和「疲惫」。两张图所表达的情绪与「累成狗」接近，但几篇标签都不包含查询的三个字，因此不会产生字面匹配。这不是 BM25 的参数选坏了：把 `k1`、`b` 调成任意合理值，没有共同 token 仍等于零。

你可以运行这段小诊断，把「相同字」和「同义」区别开：

```python
import json
import sys
from pathlib import Path

sys.path.insert(0, "scripts")
from retrieval import BM25, tokens

docs = json.loads(Path("data/sample/memes.json").read_text(encoding="utf-8"))
baseline = BM25(docs)
for query in ("累成狗", "疲惫", "量子力学"):
    print(query, [(term, baseline.df[term]) for term in tokens(query)])
    print(baseline.search(query, k=3))
```

如果输出里「量子力学」反而有候选，检查被命中的词频，通常能看到「努力」里的一字。**字面有重叠可能不相关，没有重叠也可能相关。** 这两个方向的错误都要入样例：只收集有同义正例的案例，很容易忽略错返；只收集台词题，会低估向量路。

## 第二步：候选来源可以决定下一次迭代

| 查询 | 正例 | 词法顺序 | 预设视觉顺序 | 关键观察 |
|---|---|---|---|---|
| 下班 | m02 | m02、m01 | m04、m07、m02 | 正例两路均有，但词法排得更早 |
| 累成狗 | m01、m08 | 空 | m01、m08、m05 | 图文示例路提供两个新增正例 |
| 猫 | m06 | m06 | m03、m06、m05 | 融合把正例排第一 |
| 量子力学 | 空 | m07 | m03、m07、m01 | 即使没有答案，也可能返回 |

两个指标解决不同问题：

- m02 在视觉路截止 Top3 时属于已有候选，如果视觉路预算只有 2，它就不再进池；不要只看最终 Recall@2 去猜它从哪一路过来。
- m06 的视觉 Recall@2 已经是 1，RRF 升到首位后 Recall 仍是 1，但 MRR 从 1/2 到 1。这样能把「没召到」和「召到了但没排好」写成两类经历。

## 第三步：制造一个 RRF 失败，再设计对照

现在给两路各一个独有正例，同时给一个共同但错误的 X。词法榜 [A,X]、视觉榜 [B,X]。同一段代码能同时量化并集上限和展示结果：

```python
import sys
sys.path.insert(0, "scripts")
from metrics import metrics
from retrieval import rrf

lexical, visual, correct = ["A", "X"], ["B", "X"], {"A", "B"}
merged = rrf([lexical, visual])
unique = set(lexical) | set(visual)
print("候选覆盖", len(unique & correct) / len(correct))
print("融合", merged)
print("首屏", metrics(merged, correct, 2))
```

预期并集覆盖 1，融合 `[X,A,B]`，首屏 Recall 为 0.5。为什么 X 胜出？它虽在每路只排第二，却能拿两次 1/62，大于 A 的一次 1/61。若把展示 K 从 2 提到 3，即使融合完全没变，Recall 也变好；因此实验要固定 K，不能拿调大 K 作为算法提升。

### 一次只改哪一层

| 干预 | 本例可能怎么变 | 需要再观察的反例 |
|---|---|---|
| 词法、视觉各保留一个名额 | A、B 同时出现 | 两路首位是同模板，能否回填 |
| 对精确台词优先词法 | 台词题的第一名不易下降 | 引号或常见短语会不会假装精确 |
| 可用时增加重排的小模型 | 有机会压下 X | 候选不足时重排仍帮不了 |
| 不改融合，扩大候选 K | 可能补回遗漏 | 固定的首屏空间没有增长 |

先在样例上用重复输入验证规则，再给一批新查询作比较。你应该能写出这句话：「失败发生在融合与截断。候选层已经含有正例，重复出现的错误候选获得跨路加分。」若是「累成狗」的词法空结果，则失败发生在候选阶段。两个诊断不能互换。

## 第四步：把结论迁移到真实图库

1. **建图库。** 保存有权使用、互不重复的图片和稳定 ID；不要拿文件序号代替 ID。为每张图记录是否含文字、图片来源和模板族。
2. **建查询集。** 至少覆盖情绪、准确配文、画面主体、无答案四类；每类记录使用场景和可接受替代表情。用多个召回候选加随机抽样做判定，减少漏标。
3. **固定环境。** 记录模型名、预处理、图库版本、两路候选 K 和展示 K。同样的标签与目录上跑纯词法、纯图文、融合三次。
4. **留失败记录。** 保存逐查询候选和得分；按「候选缺失」「已召回但排后」「被过滤」「标签歧义」统计。同样的错误不要重复算到不同原因里。
5. **只改一项。** 先选一个能复验的方案，比如仅将字符切分改为字二元组并保留短查询回退。重新建索引、跑全套查询、记录改善和退化。
