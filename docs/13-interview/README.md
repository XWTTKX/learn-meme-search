# 13 · 模拟面试：从表情包检索讲到模型、索引和诊断

> 训练方式：先看题目，不读答案，试着用「定义 → 项目例子 → 如何验证」答 30 秒。再展开追问，考察自己会不会把工程边界和实际成绩混在一起。

## 13.1 基础：开场三问

### Q1. 你做的这个项目满足哪几种意图？

**答：** 我区分固定台词、情绪表达和画面实体。台词适合用 OCR 或人工标签做明确词法匹配；情绪常没有相同字面，需要图文候选；实体依靠图像/文本描述，最好有语义和词法交叉验证。最终结果只在可见图库内展示，并限制重复模板。

**追问：** 「辛苦了」一定是找辛苦的人吗？不一定，用户可能想回复别人表达慰劳。应该让标签写清使用意图、允许哪些表情类型，而非只标一个近义词。

### Q2. BM25 比只按关键词计数多了什么？

**答：** 同一个字出现在很多图片里时区分度较低，所以有全库 DF 与 IDF；同字重复四次不应直接四倍，用饱和项；长标签更容易偶然命中，用长度修正。本项目的「疲惫」两图 TF 与 DF 一样，m08 短一个 token，实际排在 m01 前面。

**验证：** 打开 [源码走读](../04-source-walkthrough/README.md)，跑 `trace_search.py`，把 `--b` 设为 0，两图同分、ID 打破平局。说出这个对照比直接从背公式开始更好。

### Q3. 为什么不用分词器直接做整词？

**答：** 字符方式对口语新词与短查询容易接入，但过于宽泛，会因「量子力学」与「努力」共享一个字而错返。可同时保留短词回退和二元组/短语路。要用固定标签与展示 K 对照长句、否定、短词和无答案组。

**追问：** 改为二元组后查询「猫」怎么办？只靠二元组无 token，应定义字符回退；不能调完长句忘记短词。

## 13.2 模型：不是记住「双塔」就够了

### Q4. 解释 CLIP 的两个方向

**答：** 批内图像和文本各编码成单位向量，相似度矩阵的每行是「一张图选文字」，每列是「一句话选图」。配对样本通常对应对角线，转置后再次算交叉熵，取两个方向平均。一个方向全对并不保证另一个方向也对。

**追问：** 一张图有多句同义文本怎么办？若只按对角线标正，其他同义可能被当负例；训练侧可做同义分组或多正例目标。数据切分仍应按模板族组，而不是按单个文件。

### Q5. 减小温度一定更好？

**答：** 它放大 logit 间隔。正确项已经明显领先时损失更小，错项领先时惩罚更大；训练稳定性和负例质量都会受影响。同一查询在推理时对所有分数乘同一个正数，排序不变，但固定阈值不再等价。

**追问：** 余弦 .6 能解读成 60% 相关吗？不能；那是方向相似，需针对业务与候选分布校准。没有正例时同样可能有很高分。

### Q6. 只用首帧的 GIF 有什么风险？

**答：** 关键字、人物表情变化可能只在后半段。首帧是最便宜的基线，再比较均匀采样、镜头关键帧或多帧池化。以动图切片看增益，记录导入时间与索引大小。不要把本项目可选脚本说成已经做完多帧服务。

## 13.3 选择：在不同假设下给不同答案

### Q7. 词法与视觉分数能直接相加吗？

**答：** 分数范围、不同 query 的尺度都不一致。先用 RRF 按名次组合，避免未校准的加法。RRF 会丢掉第一名到底领先多少的信息，也可能奖励共同错项。对精确台词可用词法保留位，但用相同候选预算验证。

**当场手算：** [A,X] 和 [B,X]，A、B 正，X 错。c=60 时 X 得 2/62，两正例各 1/61。最终 Top2 只有一个正例，候选覆盖仍是 100%。

### Q8. 索引升级后召回掉了，先调什么？

**答：** 固定同一图库和向量做精确对照，把 ANN TopK 重合与对人工标签的 Recall 分开。若 Flat 和 ANN 都低，查数据或编码；若只有近似榜低，查搜索宽度、度量、归一化和版本。截图内容和 ID 不一致时先查映射。

### Q9. 词法和向量并行，端到端延迟怎样算？

**答：** 两路并行阶段取墙钟较慢者，整个请求还包含查询编码、排队、融合、过滤、序列化和网络。P95 不能简单将组件的几个 P95 相加或只取 max，应该在请求级测。记录超时触发降级，降级请求也包含在总体质量和延迟里。

## 13.4 诊断与证明

### Q10. Top1 只命中一个、Recall 却 .5，NDCG 怎么还是 1？

**答：** 一共有两个正例，Recall 分母仍是两个。NDCG@1 的理想列表也只能放一张，首位命中得到满分。看 [第 10 章](../10-evaluation/README.md) 的格子，再试 K=2；不要只看一个指标判断覆盖。

### Q11. 离线性能看似很好，用户为什么不满意？

**答：** 可能标注允许某些宽泛匹配、展示结果重复、实际查询分布不同，也可能超时频繁回退。抽查同一 query 的结果、分路、分群及服务版本；补上模板级、无答案、首位和延迟切片。真实用户体验需要独立在线证据。

### Q12. 如果测试集有许多相同图片的改字版本怎么办？

**答：** 先近重复聚类，按模板组分训练和测试；不应该分完再按单文件去重。按任务分别保存语义相关和同图替换的定义。若上游数据无法审计，结论限制在样本并公开说明。

### Q13. 你项目现在完成到哪里？

**答：** 已跑标准库词法、RRF、指标与逐词诊断，能够复现两个正例进池却首屏丢一个，以及无答案仍返回的例子。图文脚本接入预训练模型，但没有自己的授权图库实验结果。下一步是做独立查询集与同口径对照，不把模拟榜当 CLIP 成绩。

## 13.5 两轮完整对话

> **面试官：** 正例进入候选了还会漏，为什么？
>
> **你：** 候选预算和展示位置不同。比如 X 在两路第二拿两笔分，A、B 分别在单路第一，X 成为第一，K=2 只剩一个正例。我先查合并前后和展示这三个层次。
>
> **面试官：** 那去掉 RRF 就好了？
>
> **你：** 看密度。如果误伤集中在精确台词，可以保留 OCR 精确位；语义查询可能因多路共享正例受益。我会保持同一候选集和 K，对台词首位 MRR、语义覆盖以及退化例做配对对照。
>
> **面试官：** 你已经验证这套在生产好用吗？
>
> **你：** 没有。我验证的是原理可复现、代码边界和教学案例；真实数据设计另有验收。我的下一步不是宣称提升，而是用标签明确哪种情况改善、哪种情况退化。
