# 14 · 对应搜广推岗位的能力

## 同一个项目换三个岗位角度

搜索方向：讲 query 意图、词法和语义互补，展示「找梗台词」与「表达情绪」两类失败。推荐方向：讲多路候选、曝光后的行为偏差、列表去重，把检索案例迁移到候选覆盖；不把人对图片的搜索点击等同于长期兴趣。广告方向：讲过滤约束、延迟预算、相关性和收益的区别；本项目没有拍卖、预算或在线广告数据，别声称做过广告排序。

复述练习：把「我做了向量搜索」改成「给定一条中文查询，在固定图片目录上先比 BM25 与图文余弦，再对齐人工相关性和延迟，观察新增命中来自哪一路」。能完整讲输入、输出、基线和证据，比罗列模型名更能体现可迁移能力。

这个项目主要覆盖搜索相关性、多模态召回、对比学习、向量检索和评测工程。它能帮助回答广告召回与创意理解问题，但不等于做过完整广告投放系统。

| 面试方向 | 可用项目证据 | 还要补的内容 |
|---|---|---|
| 搜索算法 | query分桶、混合召回、NDCG | Learning to Rank、点击偏差 |
| 推荐算法 | 双塔向量与ANN | 用户兴趣、序列、多目标 |
| 广告算法 | 召回效率、图文相关性 | CTR/CVR、校准、竞价、预算与归因 |
| 算法工程 | 索引版本、缓存、测试 | 真实流量容量和发布系统 |

广告面试可解释 `预期价值≈pCTR×pCVR×转化价值` 的建模思路，但不同计费与拍卖机制会改变排序规则；不要背成所有平台的固定公式。推荐项目补足用户侧建模，两个项目应形成互补。

准备顺序：概率统计和机器学习基础 → 召回排序 → 项目证据 → 系统设计 → 编程题。招聘要求随岗位变化，仓库不编造“大厂统一要求”、岗位数量或薪资数字。用具体JD逐项映射自己的证据即可。
